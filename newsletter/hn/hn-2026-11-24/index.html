GLM-5.4：用循环 Transformer 走向“广义编程”

智谱发布 GLM-5.4，称为其首个基于循环 Transformer（Loop Transformer）架构的旗舰模型。与标准 Transformer 每层只跑一遍不同，它把一组权值共享的层多次迭代，用以在不增加参数量的前提下加深有效计算。官方写道，GLM-5.4 把 GLM-5 基座中的 28 层共享权重并执行两遍，规模约 7500 亿参数，并称其智能水平可与 2 到 3 万亿参数的模型相比。为控制大模型的部署成本，团队加入了按 token 的门控渐进更新、跨循环共享再加滑动窗口的混合 KV 缓存，以及第二轮复用第一轮稀疏注意力索引，目标是在百万级上下文下降低开销。文章把目标称作“广义编程”（Generalized Coding）：用代码去生成和编辑视频、搭完整游戏、做 FreeCAD 级机械设计和三维场景。局限也被写明：模型容易陷入过长的“马拉松式思考”，尽管这种反复自我纠正往往能换来超出参数量的准确率。官方计划在完成安全加固后开放模型权重，API 尚在准备中。

讨论里最先被追问的是评测数字。不少人认为旗舰模型几乎不公布分数，可能是成绩不够好看，或是反蒸馏压力下的自我保护；也有人反驳说 300 亿参数对照实验已经写在文中，不“刷榜”反而值得肯定。技术上，评论区分了隐藏状态上的循环和输出端思维链循环：前者是架构深度，后者是生成 token，二者不是一回事。有人把它和 OpenAI 据传也在做的循环深度、以及“神经语”（neuralese）的不可解释性担忧联系起来。另一些讨论集中在开源节奏：官方说开放权重前会弱化网络安全能力，因此 API 版与开源版可能不同。还有人怀疑当前架构改进已经不如数据与强化学习重要，但整体仍觉得在预训练基座上续训出循环结构，仍值得关注。

站长称收到 Arm 律师通知，AArch64 文档站将于 12 月 4 日关停

独立站点 “Jon's Arm Reference” 长期提供 Armv8-A 与 Armv9-A 的 AArch64 指令集和系统寄存器检索。站长 Jon 在首页置顶声明：应 Arm 要求，网站将于 2026 年 12 月 4 日停运。他写道，Arm 的律师已通知其下线网站，否则将面临法律行动；同时感谢这些年的用户（包括 Arm 内部的使用者），并表示会寻找办法，尽量让已有书签和链接继续可用。网站目前仍可浏览指令与寄存器列表。

HN 上有人贴出互联网档案馆备份，猜测会有更多镜像。争论的核心是版权：有人认为公开售卖的芯片文档应当允许第三人整理检索，也有人指出该站内容很可能逐字来自 Arm 手册，版权问题就在于复用手册文字是否超出介绍硬件的范围。站长本人现身说，项目眼下并未开源，但考虑在去除 Arm 知识产权后开放。还有评论观察到，近几年来 Arm 对架构与内部信息越来越封闭，猜测可能与 RISC-V 竞争、Arm China 或其他企业惯性有关。不少人怀念英特尔当年会把指令集手册直接寄给爱好者的年代，觉得芯片公司本应希望开发者更了解自己的产品。

浏览器与系统实验

Ladybird 浏览器进入 alpha，可在 macOS 与 Linux 下载

Ladybird 浏览器作者 Andreas Kling 宣布项目进入 alpha，可在 macOS 与 Linux 上下载。他强调引擎是从零写起的新内核，不是某家现有浏览器的分支；外壳尚且朴素，但已经能用。作为 alpha，部分网站会坏，也难免崩溃——浏览器内可报告坏站，崩溃后可选择是否提交报告。团队欢迎安全研究人员报告问题，并提醒 alpha 版本暂不作安全承诺。alpha 走滚动更新通道，将定期自动推送，这被 Kling 视为最令人兴奋的一点：此前要亲眼看到快速迭代，往往只能自己编译。它已支持 WebDriver 自动化测试，以及 Firefox 开发者工具协议。Kling 感谢赞助者和多年来测试、报错与写代码的人，并邀请网站开发者把自己的站点放进 Ladybird 试一下。

讨论的情绪以祝贺和亲自试用为主，有人直接用 Ladybird 发帖，用户代理字符串里仍带有 AppleWebKit 与 Chrome 的兼容标识。有人怀念它与 SerenityOS 时代“全部自己写库”的黑客气质，也注意到项目已改用 SQLite、Skia 等更成熟的组件，意见分裂在“这是必要的工程化”还是“用 Chromium 生态的库有作弊之嫌”。广告拦截是高频需求，有人安装后发现已内置可自定义过滤列表的内容拦截。安全仍是最大担心。还有人问起人工智能在开发中的比重，有回复指向 Kling 用大模型把 LibJS 迁到 Rust 的博文，同时有人强调他有 WebKit 和多年浏览器经验，与“纯氛围编程”不是一回事。

XNU Linux 尝试在 Linux 环境运行 macOS 应用和桌面

开源项目 XNU Linux 展示了一项兼容性实验：把开源 XNU 内核编译成 arm64 Linux 的可加载模块，让 macOS 与 Linux 的应用进程在同一套系统上并行运行。作者报告，项目已在 Apple Silicon 的 Linux 虚拟机和英伟达 DGX Spark 上显示 macOS 的登录窗口和桌面，并运行 Finder、Safari 等应用。仓库不分发 Apple 二进制文件；Linux 与 XNU 部分分别按 GPL 与 APSL 许可发布。

HN 读者想到的用途包括在 Asahi Linux 上保留 macOS 桌面，或减少为了使用 Xcode 而切换系统的次数。讨论同时关心软件许可、硬件支持及性能边界；目前它仍是工程演示，不是可直接替换双系统的产品。

应用分发与在线服务

开发者称开源笔记应用 FSNotes 被欧洲区 App Store 下架

开发者 Oleksandr Hlushchenko 在公开信中说，自己维护九年的开源笔记应用 FSNotes 被欧洲区 App Store 下架，10 月分成也未到账。他称已提交欧洲数字服务法要求的商家信息和企业登记文件，分别在 11 月 5 日、17 日提交了支持工单，仍没拿到明确解释。应用仍可在 GitHub 免费下载。开发者担心的不只是暂时掉销量，也包括下架后搜索排名与用户发现渠道受损。

HN 有读者从荷兰区商店的缓存页面推测，问题可能与商家身份核验有关。开发者回应说，要求的材料已经提交，最大的障碍是无法与苹果沟通。其他独立开发者也分享了找不到有效支持渠道的经历，认为对上架九年的应用，几周的断档比新应用等待审核更难补救。

Kagi Mail 公开测试：隐私邮件与日历，可用自有域名

Kagi 宣布电子邮件与日历服务 Kagi Mail 进入公开测试。用户可使用 @kagimail.com 或自有域名，按 Kagi 的说法，服务提供不限数量的别名和域名、内置日历和 50 GB 空间。它自建了托管与客户端，底层是开源的 Stalwart 服务器以及 IMAP、JMAP、CalDAV，因此也可用苹果邮件、Thunderbird 等第三方客户端。智能功能包括用自然语言整理邮件、收件箱要点、询问邮件内容（含扫描件和图片中的文字），以及把通讯当作信息流阅读；这些都可以一键关闭。隐私方面默认拦截或通过代理加载跟踪像素及远程图片，并对新发件人进行筛选。定价为 60 天免费试用后每年 99 美元（另加税），Kagi Ultimate 订阅已包含该服务。通讯录约 2027 年一季度，原生移动应用约三季度。公司承诺无广告、不画像、不锁定，离开后仍可在六个月内读取并导出邮件。

评论区的热情和犹豫差不多各半。有人觉得这是真正能跟 Proton Mail 竞争的产品，也有人被 kagimail.com 这个域名劝退，不过可以绑定自己的域名。价格是最大阻力：Fastmail 约每年 60 美元、Migadu 更低，99 美元让不少已经离开 Gmail 的用户表示继续观望；支持者则认为内置人工智能会推高成本，而且 Ultimate 用户不用另付费。信任问题同样突出：有人担心邮件并非用户侧加密、将来管理层或私募股权变化后如何保证不扫描内容，也有人对 Cloudflare Turnstile 指纹提出质疑。还有人把 Kagi 搜索近来的稳定性问题当作劝退理由。总体来说，大家认可它补上了“搜索、浏览器之后的收件箱”这一块，但还不一定愿意把最核心的邮箱交出去。

SPELUNKR：用互联网档案馆里被遗忘的影像做免费电视网

SPELUNKR 自称是一家免费的“另类电视网”，节目来自互联网档案馆里那些被遗忘的影像，宣称 24 小时同步直播，目前有 37 个频道、累计约 4395 小时内容。页面被做成老式电视节目指南：有周六早间动画、黄金时段经典剧、辛迪加重播，也有《电脑编年史》、鲍勃·罗斯的快乐画树、自然纪录片，以及《X 档案》《双峰》等片段。打开页面即可按频道观看，不必逐个寻找视频。

HN 上的反应非常直接：有人刷到超时空要塞和老动画频道，有人被文森特·普莱斯的黑白惊悚片接住，有人说第 12 频道全是鲍勃·罗斯、第 13 频道是《电脑编年史》，“光这点就值回票价”。设计被夸成“瞬间回到八九十年代的电视”，连广告都有人觉得亲切。实用建议集中在能不能出 M3U/XMLTV 以便丢进现有 IPTV 播放器或苹果电视，以及要不要把几千小时下载到本地硬盘，免得一直占用档案馆带宽。也有人询问档案馆是否在意这种绕过其官网界面的用法，多数觉得以档案馆的理念不太可能反对，而且流量未必会大到成为问题。
