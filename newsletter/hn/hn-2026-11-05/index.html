一、AI 类科技

AI 正在逼我们偿还四十年技术债：PHP2Shell

IEEE Spectrum 报道称，十月末曝出的 PHP2Shell 危及大量运行 WordPress / Drupal 等 PHP 站点的系统（含 NASA、维基百科、白宫等）。漏洞根源于 2024 年已报但长期未修的内存越界崩溃；在 OpenAI 赞助下，安全公司 Calif 借助 AI 工具在两周内把「只会崩」的问题推进成可远程执行任意代码。Columbia 的 Suman Jana 指出，这类利用需要大量琐碎但可机械化的推理，AI 正让顶尖与次顶尖专家的产能同时抬升；而修复仍须四人团队耗时约两月，暴露「找洞易、补洞难」的非对称。文章把现象概括为：人类过去四十年写下的遗留软件，正在 AI 时代被迫集中还债。

HN 多数把 PHP2Shell 读成「vulnpocalypse」前奏：有人希望国家库存的 0-day 也被顺带扫出，换来更硬的软件底座；也有人警惕「协调披露太慢、任何人都能用 AI 复现」。另有观点批评产业长期用地址消毒等检查方案代替内存安全语言，并担心 LLM 会无节制堆代码、制造更多攻击面。整体语气是焦虑加务实——技术债账单已到，防御方人力与开源维护资金更吃紧。

Tell HN：Gemini 对个人订阅用户仍用聊天记录训练

主帖作者引用 Google 支持文档指出：个人 Google AI 订阅若开启「Keep Activity」，Gemini 保存的聊天可用于改进服务与训练生成式模型，且部分对话可能经人工审阅；人工审阅过的内容在删除活动后仍可保留最长三年，官方还明确提醒「不要输入不想让审阅者看到的机密信息」。若关闭 Keep Activity 以退出训练，聊天只会保留约 72 小时。作者原本以为「付费就不会被当产品」，结果发现付费仍不够。

Anthropic：大模型可证明推理（FlashProve）进展

Anthropic Frontier Red Team 发布 FlashProve：用 zkSNARK 让服务商对权重做承诺，并为每次回复生成短证明，用户无需知道权重即可验证「响应确实来自所声称的模型」。对 Llama 4 Maverick（约 400B MoE、4-bit）单卡 H100 可做到约 110 tok/s 出证、每 1024 token 请求约 19MB 证明；相对 vLLM 推理约 70–95× GPU 时间。代码、Lean 形式化与技术报告开源（Apache 2.0），并讨论 pacing、篡改检测与文本出处等应用场景。文章强调仍是原型：目前主要覆盖贪心解码的整数近似、短上下文，且隐藏架构不在目标内。

Nvidia RTX Spark 加密固件限制 Linux 推理性能

MindStudio 实测 MSI Prestige 等 RTX Spark 笔记本：双系统可装 Linux 并启用 Nvidia 开源驱动与 CUDA，但接上电源后 GPU 时钟被锁在约 780 MHz（Windows 可达约 2.2 GHz）。GPT-OSS-120B 上 Windows / WSL 约 65 tok/s，原生 Linux 仅约 13.9 tok/s；根因是 Windows 独有的 Nvidia Platform Controllers and Framework 负责 CPU/GPU 功率表，而固件功率表加密、Linux 无法解密。有趣的是断开外接电源、改用电池时 Linux 接近满速，插电反而暴跌。作者结论：现阶段 WSL 才是务实方案，真正修复需 Nvidia 把平台控制器逻辑移植到 Linux 驱动。

HN 先纠正标题曾误写成 DGX Spark（桌面 Linux 机与笔记本不是一回事）；随后有人猜测「以后会不会变成付费解锁才能本地跑未授权模型」。也有人吐槽小标题那种三点列举的「Claude 味」修辞。工程讨论仍集中在统一内存 AI 笔记本的系统支持：在 Windows on ARM + CUDA 环境下，原生 Linux 的支持不足，WSL 是目前可用的替代方案。

C++26 DIS 未获批准：Contracts 争议把标准带入僵局

C++ 委员会成员 Andreas Fertig 撰文称：2026-10-23 ISO 国家成员体对 C++26 DIS 投票结果为 Disapproved，据他所知是 C++ 历史上首次 DIS 失败（除开多年前的 C++/CLI）。反对意见集中在 Contracts（契约/前后置条件）尚未成熟。文章梳理 Contracts 自 C++20 起反复进标准又被拿下的历史，并指出 WG21 内部此前已多数赞成带 Contracts 前进，但 NB 层否决打破惯例。后续可选修订再 DIS、退回 CD、发 TS 或取消项目，任一路径都意味着延迟，而委员会两派都已投入多年，信任受损，下一场会议（11 月 16 日）必须破局。

HN 一边科普「Contracts ≈ 可编程的前后置条件/断言」，一边争论内存安全是否该借这次停摆被更认真对待；也有人感慨标准化共识崩塌像更大社会信任流失的缩影。原文涉及较多委员会内部程序，不少读者抱怨「到底什么是 Contracts」，评论区被迫现场补课。整体气氛是危机感与程序正义争议重于具体语法设计争论，对 C++29 命运的悲观预期不低。

Go 1.27：稳定的 encoding/json/v2

Go 官方博客宣布实验多年的 encoding/json/v2 与 encoding/json/jsontext 在 Go 1.27 稳定可用。v2 针对无效 UTF-8、对象重复键、nil slice/map 编成 null、字段名大小写不敏感匹配等老问题给出更安全的默认行为，并引入真正流式的 Encoder/Decoder，以及 MarshalJSONTo / UnmarshalJSONFrom 等面向流的接口；反序列化基准最高可提升约一个数量级。v1 将长期保留且底层改用 v2 实现，两套可互操作，还提供选项让调用方按行为差异逐步迁移。

HN 老话题立刻重开：有人抱怨 Marshal 为什么还要返回 error，觉得更该是编译期或直接 panic；多数回复指向 NaN/Inf、懒加载失败、自定义 MarshalJSON 等运行时才知道的情况。也有人对真正流式 API 与反序列化性能改进表示欢迎，并讨论迁移成本。典型语言标准库演进帖，抬杠与建设性补丁说明大致参半，整体偏技术向。

昆虫不太围着 LED 灯打转

自然博主 Kate St. John 结合导游观察与布里斯托大学 2016 年实验解释：飞虫靠月光中的紫外导航，把「光打在背上」当姿态参考；白炽灯含 UV，LED 几乎不辐射 UV，因而显著更不招虫。家庭改 LED 后壁虎不再聚集灯光附近，文章认为这与食物（飞虫）变少有关，并不表示壁虎消失。文章也引用研究称人工夜间照明干扰昆虫繁殖，LED 相对减轻这一压力，同时评论区提醒蓝光对昼夜节律的新问题。

HN 立刻用自家体验「打脸」：家里全是 LED 仍有蛾子、蜜蜂往亮处飞。回应者指出原文说的是「显著更少」，并未声称飞虫「绝迹」，还建议旁边留一盏白炽灯做对照；另有人提出 PWM 调光闪烁可能让复眼动物更难受的假说。整体是科学向轻松帖，评论区还附带指向昆虫种群下降多因子综述的链接，提醒 LED 只是叙事的一块拼图。

三、城市与交通
