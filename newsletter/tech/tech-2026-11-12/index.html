产业与资本

a16z：欢迎来到“企业对智能体”经济

a16z 的 Olivia Moore 与 Justine Moore 提出，人工智能智能体正成为互联网的主要使用者：它们占据大部分网页流量，写出过半的新文章，也生成了大多数进入生产环境的代码。文章把这种变化称为“企业对智能体”（B2A）经济——过去平台花几十年把机器人挡在门外，现在却要争着做它们的生意。因为智能体正从回答问题转向完成任务，会越来越多地决定用什么产品、订什么服务、把钱花到哪里。已有数据支持这一转向：Shopify 称 2026 年第一季度由 AI 带来的进店流量同比增长 8 倍，由 AI 搜索促成的订单接近增长 13 倍；Human Security 观察到 8 月至 10 月智能体浏览器流量增长 8 倍。编程领域已是先例：到 2026 年 9 月，超过 40% 的 GitHub 拉取请求以智能体草稿起步，半年前还只有 17%；Supabase、Stripe、Vercel 等基础设施公司也报告，新数据库和部署越来越多由智能体发起。作者认为，真正的平台变迁还需要新的分发机制，而多数企业仍因欺诈和拒付风险在阻挡智能体流量。

Latent Space：用语音和云端交接管理 Codex

Latent Space 的 Richard MacManus 旁听了 AI Engineer Code Summit 上 OpenAI 开发者体验工程师 Dominik Kundel 与 Charlie Guo 的工作坊，主题是如何用语音、云端交接和个人助手（dots）来使用编程智能体 Codex。Codex 最初被定位为可并行处理多项任务的云端工程智能体，但云端体验长期别扭；今年 9 月底 DevDay 推出的 Codex Cloud 第二版后，开发者可以先发布一份环境，再在隔离实例中跑多个任务，本机与云端也开始互相交接。语音不只被当作打字的替代，Guo 更愿意把它当成控制平面：用嘴管理多个线程、查看进度、从其他应用取数据。dots 对重度用户仍有些别扭，但可作为安全网、在 Slack 里承接委派，以及在各处保持上下文；Kundel 常在通勤时对 dot 口述，让它先起草拉取请求，到公司后再审阅。工作坊的提醒是：不要把当前用法固定下来，因为产品仍在快速变化。

Peter Yang：如何在 Claude Code 中选择 Fable 与 Opus

Peter Yang 根据自己在 Claude Code 中超过 500 小时的使用经验，比较 Anthropic 新推出的 Fable 5.2 与仍很强的 Opus 5.5。他认为 Fable 在多数任务上更聪明，包括编程和长时间运行的智能体，但每个 token 的费用大约是 Opus 的两倍，而且在 Max 套餐里最多只能占用每周额度的一半。因此他的建议是：把 Opus 当作日常主力，把 Fable 留给最难的工作。Anthropic 研究员 Alex 还建议：先让 Fable 指出想法的问题再动手；使用中等推理强度；事先说明哪些步骤必须经你批准；把整个项目交给它，而不是一次只给下一步。Yang 自己用 Opus 处理邮件、自动化流程和做个人应用，用 Fable 做商业策略咨询、协助照顾患病的母亲，以及检查自己的 AI 工作流是否有漏洞。文章后半还有可复制的设置提示，完整用例需阅读原文或观看视频。

可靠性与安全

Slow AI：AI 协助如何影响人的纠错能力

斯坦福大学与英国 AI 安全研究所的一项研究，让 416 人判断人工智能输出在事实、偏见和危险行为上是否正确，共作出 35,613 次判断。总体正确率几乎没有变化：独自检查时为 62.5%，在两种 AI 助手帮助下分别为 61.7% 和 64.5%。可一旦按“模型当时是对是错”拆开，差异就很大：模型说对时，有助手的人表现更好；模型说错时，人们发现错误的比例从 36.7% 降到 20.6%。两种效应互相抵消，所以汇总数字看起来像“什么都没发生”。Slow AI 据此提醒：平均成绩把做对的部分和被模型带偏的部分混在一起，掩盖了人们在识别模型错误时的表现差异。

Architect’s Notebook：PUT 与 PATCH 究竟差在哪里

Amit Raghuvanshi 用电商改资料的例子，讲清 PUT 和 PATCH 这两种修改资源的 HTTP 方法有何不同。PUT 的意图是用一份新的完整表示替换当前资源，请求里没写到的字段，按接口约定可能会被重置或删除，因此客户端不应假定“没写的就保持不变”。PATCH 则只提交要改的部分，例如只改电话号码，其余字段保持原样；它可以使用 JSON Merge Patch 或 JSON Patch 等格式，服务器必须理解相应语义。PUT 被定义为幂等：同一请求发送多次，效果应与发送一次相同；PATCH 并不天然幂等，比如“余额加 100 元”每执行一次结果都会变，但也可以设计成幂等。常见面试简答“PUT 改全部、PATCH 改一个字段”并不准确：PATCH 可以改多个字段，PUT 在目标不存在时也可能创建资源。设计可靠接口时，还应考虑用 ETag 和 If-Match 这类条件请求，避免两人同时更新时互相覆盖。

Ars Technica 报道，安全公司 Claroc 发现 SpaceXSI 的编程智能体 Grok Build 使用可分享的 *.grok.me 链接，其随机词前缀位于域名左侧，可通过被动 DNS 枚举。Claroc 统计到逾 4.3 万个链接，其中 3.5 万个以上可公开打开应用及其数据，内容包括商业计划、医疗检查面板、员工名册，以及 24 个由 SpaceXSI 自己搭建的应用——其中含企业销售入职材料、约 594 个账户的销售区域图和内部工具地址。Claroc 称已于周日通知公司；Ars 发问后，这 24 个内部应用链接开始被撤下，但报道上线时多数其他数据仍可访问。The Verge 补充了官方回应：Grok 称该文不准确，指的是 grok.com 上的应用构建功能，并说用户在发布前会核对分享设置并看到警告。

OpenAI：思维链监控如何随模型训练变化

OpenAI 的 Jeffrey Wang 等人研究了预训练、模型架构、强化学习和合成训练数据如何影响思维链的可监控性。他们发现，基础模型越强，不写出思维链也能完成推理的能力通常越强；模型按要求增删或操纵思维链文字的能力也有所提升。强化学习中，即使只约束输出长度、评判最终答案，这种操纵能力仍会明显增加；用较强“教师”模型生成的数据训练，还可能把这一特征传给下一代。研究同时强调，操纵思维链的能力只是带有噪声的替代指标：在所比较的一对能力相近的模型中，它与实际逃避监控没有表现出显著关联。因此，结果支持继续研究监控能力如何随训练变化，不能直接推成所有强模型都已能隐藏意图或绕过安全检查。

半拿铁：文曲星的三十年往事

《半拿铁｜商业沉浮录》第 226 期由刘飞、潇磊回顾文曲星和远见科技的三十年。电子词典原本是家长购买的英语学习工具，却成了一代人的游戏掌机和编程启蒙；节目资料称，文曲星在 2000 年的市场份额约为 73%，同年推出支持 GVBasic 的 CC800，使用户能够自行编写程序和游戏。随后，步步高、诺亚舟、好记星进入竞争，学习机把重点转向课程、语音互动和记忆训练，智能手机又改变了便携计算的使用场景。节目追踪文曲星尝试 Linux 掌上电脑后的转型困局，以及远见科技逐渐依靠不动产租赁收入的过程：到 2024 年，租赁业务已约占全年营收的 80%。约 106 分钟的回顾把产品、渠道和用户社区放在一起，也讨论电子词典退潮后，教育硬件市场为何仍在延续。

Every：自动化之后人的工作

Every 发布了 Dan Shipper 在 Thesis: 2027 的闭幕演讲，讨论自动化之后人的工作。Shipper 区分两种看未来的方式：从总体数据和基准测试外推，容易看到模型不断超过人；走近一个人的实际工作，则能看到人也会借助同一批模型提升能力。他举例说，团队成员把同一份客户调查交给 Claude，却分别发现退订原因和读者孤独感等不同问题。模型能够生成多种见解，决定优先处理哪一个，仍需要人的立场和对某项工作的责任。他据此主张，用“能否从我的角度做好我的工作”评价模型，而不只盯着有标准答案的数学和编程题。公开视频约 27 分钟；这种判断来自 Every 的工作案例，不把基准成绩直接等同于未来岗位数量。
